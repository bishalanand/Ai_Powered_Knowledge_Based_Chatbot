RAG FAQ Chatbot — Project Documentation
1. Project Overview

This project implements a Retrieval-Augmented Generation (RAG) chatbot that answers questions from uploaded PDF documents.

Instead of relying only on an LLM’s internal knowledge, the system:

Extracts text from PDFs

Converts the text into vector embeddings

Stores them in a vector database (Pinecone)

Retrieves relevant chunks when a user asks a question

Sends those chunks to an LLM (Ollama Llama3)

Generates an answer based on the retrieved context

2. System Architecture

The pipeline follows this structure:

User Question
      ↓
Retriever (Pinecone)
      ↓
Relevant Text Chunks
      ↓
LLM (Ollama - Llama3)
      ↓
Final Answer

Full system flow:

PDF Upload
   ↓
Ingestion Pipeline
   ↓
Text Chunking
   ↓
Embedding Generation
   ↓
Vector Storage (Pinecone)
   ↓
Retriever
   ↓
LLM (Llama3)
   ↓
Chatbot Response

4. Module Descriptions
4.1 Ingestion Module

File:

src/ingestion/ingest.py

Purpose:

Convert PDF documents into vector embeddings and store them in Pinecone.

Pipeline:

PDF
 ↓
Load document
 ↓
Split text into chunks
 ↓
Create embeddings
 ↓
Store vectors in Pinecone

Key operations:

PDF Loading
PyPDFLoader

Extracts text from the document.

Text Chunking
RecursiveCharacterTextSplitter

Parameters:

chunk_size = 800
chunk_overlap = 150

Purpose:

Split large text into smaller pieces so the retriever can search efficiently.

Example:

Document
   ↓
Chunk1
Chunk2
Chunk3
Embedding Generation

Model used:

sentence-transformers/all-MiniLM-L6-v2

This converts text into numerical vectors.

Example:

"What is refund policy?"
↓
[0.34, -0.18, 0.92, ...]
Vector Storage

Vector database:

Pinecone

Stored information:

vector
metadata

Example metadata:

{
 doc_id: "faq",
 source: "faq.pdf"
}
4.2 Retriever Module

File:

src/retrieval/retriever.py

Purpose:

Retrieve relevant document chunks from Pinecone.

Pipeline:

User Question
      ↓
Convert to embedding
      ↓
Similarity Search
      ↓
Top K Results

Configuration:

k = 5

Meaning:

Retrieve top 5 most relevant chunks

Filtering:

filter={"doc_id": doc_id}

This ensures the retriever searches only inside the selected document.

4.3 LLM Module

File:

src/llm/chatbot.py

Purpose:

Generate answers using the retrieved context.

Model used:

Ollama Llama3

Pipeline:

Retrieved Chunks
      ↓
Prompt Creation
      ↓
LLM
      ↓
Answer

Chain used:

RetrievalQA

This combines:

Retriever + LLM
4.4 RAG Pipeline Module

File:

src/pipelines/rag_pipeline.py

Purpose:

Connect the retriever and chatbot together.

Pipeline:

doc_id
   ↓
get_retriever()
   ↓
create_chatbot()
   ↓
QA Chain

This module acts as the system orchestrator.

8. Known Limitations

Current system limitations:

Single-document chat

Only one document is used per session.

No Web Interface

Interaction happens through terminal.

Duplicate ingestion risk

Re-uploading the same document may create duplicate vectors.

Slow first response

LLM loading may take 30–60 seconds.

3. COMPLETED BACKEND COMPONENTS

---

1. PDF Ingestion Module

File: src/ingestion/ingest.py

Features:

* Loads PDF using PyPDFLoader
* Splits document using RecursiveCharacterTextSplitter
* Chunk size = 800
* Chunk overlap = 150
* Adds metadata:

  * doc_id
  * source
* Generates embeddings using:
  sentence-transformers/all-MiniLM-L6-v2
* Stores embeddings in Pinecone
* Deletes old vectors for the same doc_id before inserting
* Returns:
  doc_id
  file_name
  number of chunks
  chunks themselves

---

2. Retriever Module

File: src/retrieval/retriever.py

Features:

* Connects to Pinecone vector store
* Uses same embedding model used during ingestion
* Creates retriever filtered by:

filter = {"doc_id": doc_id}

This ensures queries only search within the selected document.

Retriever settings:
k = 5

---

3. Chatbot Module

File: src/llm/chatbot.py

Features:

* Uses ChatGroq
* Model used:

llama-3.1-8b-instant

* Creates a RetrievalQA chain using:
  retriever
  LLM

Returns:
qa_chain

---

4. RAG Pipeline

File: src/pipelines/rag_pipeline.py

Purpose:
Combine retriever + chatbot

Steps:

1. Create retriever using doc_id
2. Create chatbot using retriever
3. Return qa_chain

---

5. Upload API

File: api/upload.py

Responsibilities:

1. Receive uploaded PDF
2. Save file to uploads directory
3. Call ingest_pdf()
4. Store chunks in shared memory
5. Return document_id

---

6. Summary API

File: api/summary.py

Responsibilities:

1. Receive document_id
2. Load chunks from shared memory
3. Pass chunks to summarization module
4. Return generated summary

---

7. Shared Memory

File: store.py

Purpose:
Share runtime memory between APIs

Stores:

chunk_store
Stores document chunks

format:
{
doc_id: [chunk1, chunk2, chunk3]
}

pipeline_cache
Stores RAG pipelines

format:
{
doc_id: qa_chain
}
